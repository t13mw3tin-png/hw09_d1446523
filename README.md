## 一、程式用途與執行方式

### 程式用途
本程式用來整理「桌遊體驗」（每人 120 元）與「電影欣賞」（每人 80 元）兩場活動的原始報名文字。程式先透過字串方法統一轉小寫並移除半形空白，再搭配 Python 內建容器進行資料處理：
- **`tuple`**：保存固定的活動名稱。
- **`list`**：保存整理後但尚未去重的名單（觀察原始報名順序與重複狀況），以及排序與切片（`[:2]`）後的通知預覽名單。
- **`set`**：去除同一場次的重複報名，並透過交集（`&`）、聯集（`|`）與雙向差集（`-`）比較兩場參加者名單。
- **`dict`**：儲存各活動單價，以及彙整各項人數與應收金額摘要。

## 三、問題回答

### 問題一：測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？

- **為什麼以 3 人計算**：整理後的串列為 `['amy', 'ben', 'amy', 'cora']`，其中 `'amy'` 只是因為大小寫與空白不同（`" Amy"` 與 `"amy"`）而重複報名了兩次。根據活動規則，同一個人在同一場活動中重複報名只算一位參加者、收一次費用，所以實際參加人數只有 3 人（Amy、Ben、Cora），桌遊應收費用為 `3 × 120 = 360` 元。
- **直接拆成 `list`**：
  - **保留了**：原始填寫的先後順序、每個人重複報名的次數與紀錄。
  - **失去了**：無法直接判斷實際不重複人數，也無法直接做交集、差集等名單比對。
- **再轉成 `set`**：
  - **保留了**：該場次所有不重複的參加者名單，並取得快速進行集合運算（交集、聯集、差集）的能力。
  - **失去了**：原本報名的先後順序，以及誰曾經重複報名過幾次的次數資訊。

### 問題二：測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。

- **集合關係說明**：在測試三中，桌遊集合 $A = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，電影集合 $B = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，兩個集合的元素完全相同（$A = B$）。
  - **總不重複人數**看的是兩場的**聯集**（$A \cup B$）：因為大家兩場都報了，聯集結果還是這 3 個人，所以總不重複人數為 $|A \cup B| = 3$ 人。
  - **報名人次**看的是兩場各自去重後的人數相加（$|A| + |B|$）：每個人都同時參加了兩場活動，因此每個人都貢獻了 2 人次。
- **算式說明**：
  - **報名人次**：$|A| + |B| = 3 + 3 = 6$ 人次。
  - **總應收金額**：兩場活動分開計費，桌遊應收 $3 \times 120 = 360$ 元，電影應收 $3 \times 80 = 240$ 元，合計 $360 + 240 = 600$ 元。
